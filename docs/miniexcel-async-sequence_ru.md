# Полный путь для `miniexcel`

1. Клиент отправляет `POST /api/v1/documents/async` с JSON-данными, `engine=miniexcel`, форматом `xlsx` и, при необходимости, XLSX-шаблоном.
2. API проверяет запрос. Redis проверяет, не обрабатывается ли уже такой же запрос. Если это новая задача, API сохраняет её со статусом `Queued` в PostgreSQL, отправляет сообщение через MassTransit в RabbitMQ и отвечает `202 Accepted` с `taskId`.
3. Worker получает сообщение, меняет статус задачи на `Processing` и проверяет в Redis, не создавался ли уже документ для такого запроса.
4. Если результат найден в Redis, Worker использует сохранённую ссылку на файл и помечает задачу завершённой. Если результата нет, Worker вызывает MiniExcel: с XLSX-шаблоном используется `SaveAsByTemplate`, без шаблона JSON преобразуется в строки таблицы через `SaveAs`.
5. Worker сохраняет XLSX в MinIO, помещает сведения о результате в Redis и записывает в PostgreSQL статус `Completed` и путь к файлу. При ошибке выполняются повторы; если они не помогли, задача получает статус `Failed`.
6. Клиент опрашивает `GET /api/v1/tasks/{taskId}`. При успехе он получает ссылку и скачивает файл через `GET /api/v1/tasks/{taskId}/download`; API читает его из MinIO.

> **Примечание:** Здесь две разные проверки Redis: первая предотвращает повторный запуск одинаковых запросов, вторая позволяет повторно использовать уже готовый документ. Polling статуса читает состояние задачи из PostgreSQL. Async-режим переносит генерацию в Worker; сам MiniExcel выполняет генерацию синхронно внутри этого фонового процесса.

# Роль PostgreSQL в async-задачах

PostgreSQL хранит **состояние async-задачи**, а не сам XLSX-файл:

- API создаёт запись о задаче со статусом `Queued`.
- Worker меняет статус на `Processing`, а затем на `Completed` или `Failed`; записывает имя результата, путь к файлу или текст ошибки.
- API читает запись для `GET /api/v1/tasks/{taskId}` и определяет, можно ли скачать результат.

Так API и Worker видят одно устойчивое состояние, даже если работают в разных процессах. Сам файл сохраняется в MinIO. Redis используется для дедупликации запросов и кеширования результатов, а RabbitMQ передаёт Worker-у сообщение о задаче.

> **Примечание:** PostgreSQL используется, когда выбран провайдер `PostgreSql` — в частности, в Docker Compose. При настройке `InMemory` постоянного хранения task-записей в PostgreSQL нет.
